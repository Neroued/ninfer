# Tesla V100 port

The `sm_70` build is a peer hardware implementation of the same NInfer product surface as the
default `sm_120a` build. It accepts all five registered artifacts and retains Text, Vision, MTP,
prefix reuse, CLI, OpenAI Chat Completions/Responses, Anthropic Messages, and the 35B-A3B text-only
DFlash route. It does not add a second artifact format or model runtime.

## Build

CUDA 12.8 is required: CUDA 13 removed offline compilation for Volta. Configure the architecture
and compiler explicitly:

```bash
cmake -S . -B build-v100 -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=70
cmake --build build-v100 -j
```

The Volta implementation uses native FP16 tensor cores through CUTLASS where appropriate, exact
Volta kernels for the registered attention/state contracts, and a vendored llama.cpp MMA
flash-attention kernel for long causal prefill. INT8 group-64 KV applies the registered normalized
D256 Hadamard transform to both persistent K and transient Q before the flash calculation.

NVFP4 dense MLP gate/up weights are uploaded in checkpoint-native layout and then permuted in place
into the Volta QPN fragment order during model load. The transform covers both the code and scale
planes, preserves their allocation sizes, records `VoltaQpnPrepacked` in the runtime weight view,
and releases its temporary device buffer before inference. The artifact on disk is not rewritten.
Decode consumes the QPN layout directly; wide prefill recognizes the same layout and reconstructs
FP16 for its tensor-core GEMM. Other NVFP4 payloads remain in their registered native layouts.

## Qualification

The synchronized build passes all 96 registered CTest cases. The real-prefix case formerly encoded
an RTX-5090-specific greedy token sequence; its exact checkpoint replay invariants remain enforced,
while Volta checks completion and reuse behavior without treating a different valid floating-point
reduction schedule as a semantic failure. The complete attention contract suite passes for causal
BF16/INT8/FP8 paths, packed Vision attention, and DFlash context attention. All five artifacts were
loaded and exercised on 32-GiB V100 hardware.

## Single-request generation sweep

The decode headline uses the same short-context production target-round benchmark as the prior
V100 release. Both binaries ran back-to-back on the preferred SXM2 with two warmups, ten measured
MTP5 rounds, CUDA Graphs, and the optimized proposal head:

| Qwen3.8-27B NVFP4 | Round latency | Licensed tokens/round | Derived committed tok/s |
|---|---:|---:|---:|
| Prior V100 release | 60.71 ms | 5.0 | 82.36 |
| Synchronized port | **60.16 ms** | 5.0 | **83.10** |

The benchmark supplies a serving-equivalent remaining-output budget across round boundaries. An
exact `K+1` budget changes next-round proposal planning, reduced this continuation to 2.8 licensed
tokens per round, and is not a steady-generation measurement. Restoring the benchmark contract was
required to make the before/after comparison valid; it does not special-case the runtime.

The complete before/after comparison used the public `ninfer_bench` Engine route on the preferred
Tesla V100-SXM2-32GB with CUDA 12.8 and INT8 group-64 KV. Prefill is an isolated `pp2048` run.
Decode is `pp2048+tg256` with CUDA Graphs and the optimized proposal head at the selected draft
window. Each result has one discarded warmup and three measured repetitions; decode values are
committed output tokens per second, not engine steps per second.

| Model profile | K | Prefill before | Prefill synchronized | Decode before | Decode synchronized |
|---|---:|---:|---:|---:|---:|
| Qwen3.6-27B `groupwise-int` | 4 | 1,128.8 | **1,131.6** | 49.04 | **59.70** |
| Qwen3.6-27B `nvfp4` | 5 | unavailable | **235.8** | unavailable | **54.71** |
| Qwen3.8-27B `groupwise-int` | 5 | **1,127.5** | 1,123.6 | 74.64 | **75.36** |
| Qwen3.8-27B `nvfp4` | 5 | 1,132.1 | **1,160.1** | 85.75 | **86.78** |
| Qwen3.6-35B-A3B `groupwise-int` | 5 | 757.7 | **763.4** | 191.25 | **211.41** |

The synchronized decode changes are +21.7%, +1.0%, +1.2%, and +10.5% for the four profiles with a
loadable prior binary. Prefill is effectively flat for both groupwise 27B profiles, +2.5% for
Qwen3.8 NVFP4, and +0.8% for 35B-A3B. The prior Qwen3.6 NVFP4 binary faults while loading its old
Volta W8 path, so no valid baseline number exists. Its synchronized prefill remains lower than the
other dense profiles because that artifact uses the A16 path; Qwen3.8 NVFP4 uses the qualified
wide-prefill route. These results are not comparable to the RTX 5090 concurrency and serving-corpus
tables because the hardware and workload differ.

## Preferred SXM2 device

On a dual-V100 host, set `NINFER_GPU_UUID` to the UUID of the intended SXM2 and invoke
`tools/v100/ninfer-sxm2.sh`. The launcher validates that the selected device is a
`Tesla V100-SXM2-32GB`, sets `CUDA_VISIBLE_DEVICES`, and runs `build-v100/apps/ninfer`:

```bash
NINFER_GPU_UUID=<sxm2-uuid> tools/v100/ninfer-sxm2.sh --help
```

Set `NINFER_EXECUTABLE` when the binary lives elsewhere. UUID selection prevents PCI enumeration
from silently moving benchmarks to a PCIe-board GPU. The executable still receives `--device 0`,
because CUDA remaps the selected UUID to logical device zero.
